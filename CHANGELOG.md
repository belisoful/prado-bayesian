# Changelog

All notable changes to `belisoful/prado-bayesian` are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

The theme of this release is production use: a model trained from many processes at once, a
service that can be restricted, stored formats that can evolve, and checks that keep the
documentation honest. Every change below is listed with what to do about it.

### Fixed
- PHP 8.5 compatibility: casting `NAN` to a string warns there, and the `bayesian_alpha_invalid` and calibration error messages did so; non-finite floats are now named (`NAN`, `INF`) in messages. The test suite no longer calls `ReflectionProperty::setAccessible()`, which PHP 8.5 deprecates. The suite runs deprecation-free under PHP 8.4 and 8.5.
- **Lost updates in per-token training.** `TSqlBayesianStorage::applyDeltas()` read token rows, added the deltas in PHP and re-inserted them, and both SQL and Redis wrote the category scalars and the model totals as absolute values from the writing process's snapshot, so two processes training one model overwrote each other's counts (and two first inserts of a token could violate the primary key on PostgreSQL). Every count is now an atomic in-store increment — driver-specific `cnt = cnt + delta` upserts in SQL, `HINCRBY` inside Lua scripts in Redis — the vocabulary size is derived from the tokens a write really added, and the document total is the sum of the category counts. A multi-process test proves exact counts on SQLite, MySQL, PostgreSQL and Redis.
- `TSqlBayesianStorage` in per-token mode failed on MySQL with a syntax error, because MySQL has no `CREATE INDEX IF NOT EXISTS`; the lookup index is now declared inline.
- Tokens longer than 191 characters (a URL from `TRegexTokenizer`, a run of characters) or not valid UTF-8 made per-token training fail on MySQL and PostgreSQL (`VARCHAR(191)`). Such tokens are stored under a fixed-width surrogate key on every driver, invisibly to callers.
- `TComplementNaiveBayes` returned `-INF` for a category whose weight norm was zero (no token distinguishes it from its complement, e.g. two categories trained on the same text, or a single-category model with a single token), so a trained model could throw `bayesian_classifier_score_undefined`. A zero norm now scores neutrally. A single-category model with one token therefore scores `1.0` for that category instead of being undefined.
- `TLazyBayesianVocabulary` accumulated every prefetched token for the life of the process; a worker that scored documents for hours grew without bound. The batch is now capped by `MaxBatchTokens` (default 50,000) and restarts from the current document when it would exceed the cap.
- `TFileBayesianStorage` accepted names starting with a dot, saving a dotfile that `list()` never returned. Such names are now rejected with `bayesian_storage_name_invalid`.
- **Concurrent untraining through SQL per-token storage.** Two processes withdrawing a token's last documents from different categories each checked the other's row before it changed: on MySQL the two checks deadlocked and one writer failed with error 1213, on PostgreSQL neither removed the token and the vocabulary size drifted, shifting every smoothed score. A token's vocabulary row is now its lock — shared by writes that add documents, exclusive for writes that withdraw them, always taken before the token rows — and a write the database still reports as a deadlock victim (SQLSTATE 40001/40P01) is retried up to five times, which is safe because it consists of increments. A multi-process test withdraws documents from four workers at once on SQLite, MySQL, PostgreSQL and Redis, for all three classifier variants.
- `TSqlBayesianStorage` reported a connection that failed to open as this extension's `bayesian_storage_pdo_connect_failed` only by accident of the trait's activation order; it now activates the connection itself and translates the failure explicitly.

### Added
- **Untraining.** `IBayesianClassifier::untrain()` and `untrainOne()` withdraw a document exactly: every count stops at zero, a token no document contains any more leaves the vocabulary (`|V|` shrinks, so the smoothing returns to what it was), and a category left without documents is removed. A model that trained and then untrained a document scores identically to one that never saw it, in every layout; per-token storage applies the withdrawal as atomic decrements, so it is safe under concurrent training. `IBayesianVocabulary::removeDocument()`, `TBayesianCategory::removeDocument()`/`removeToken()`/`removeTokenDocument()` and `TLazyBayesianVocabulary::withdrawDocument()` are the pieces.
- **Probability calibration.** `TNaiveBayesClassifier::calibrate(TBayesianTrainingSet $heldOut)` fits a `TTemperatureScaling` (one temperature, golden-section search on the held-out log-likelihood) and installs it, after which `score()` returns calibrated probabilities; `logScores()` returns the raw log-posteriors; `getCalibration()`/`setCalibration()`/`getIsCalibrated()`. The calibration is saved with the model (`calibration` in payloads and per-token metadata; the payload format stays 1, older readers ignore the key). `TPlattScaling` fits a logistic curve over a binary decision value. `TCalibrationMetrics` (log loss, Brier score, expected calibration error, and their distribution forms) judges a calibration on held-out data. The service's `classify` response gains `"calibrated": bool`.
- **Multi-label tagging.** `TBayesianTagger` (`IBayesianTagger`) trains a document under each of its labels plus a background category and derives an exact one-versus-rest Naive Bayes decision per label from the shared model, so labels get independent probabilities, training costs one write per label plus one, and every storage layout works unchanged. `train()`, `untrain()`, `probabilities()`, `tag()` (with `Threshold` and `MaxTags`), `logOdds()`, `calibrate()` (a `TPlattScaling` per label, saved with the model through the classifier's new extra state), `getLabels()`, `BackgroundCategory` (default `*`, reserved as a label). The service gains `action=tag`, the `bayesian_tag` permission (`dyTag`), and `TagThreshold`/`MaxTags` properties.
- `TNaiveBayesClassifier::getExtraState()`/`setExtraState()`: JSON-serializable state other components keep with a model, saved and loaded with it.
- **Bernoulli and Complement train incrementally through per-token storage.** Their per-category aggregates are sums over the whole vocabulary, which a storage-backed vocabulary cannot walk; in 0.1.0 the first `trainOne()` on a loaded per-token model of either variant left it unable to classify. Both aggregates are now computed from integer "count of counts" histograms (`TBayesianTokenHistogram`) that `TSqlBayesianStorage` and `TRedisBayesianStorage` keep current inside the same atomic unit as the token counts (new `IBayesianHistogramStorage`: `loadTokenHistograms()`, `rebuildTokenHistograms()`; `TLazyBayesianVocabulary::getTokenHistograms()`; `TNaiveBayesClassifier::getHistogramFamilies()`). Resident and storage-backed models take the same sum in the same order, so they score identically bit for bit, under training, untraining and concurrent writers; a multi-process test proves it on SQLite, MySQL, PostgreSQL and Redis. The multinomial classifiers name no histogram family and pay nothing. **Migration:** SQL gains a `<Table>_hist` table, created automatically unless `AutoCreateTable` is off (then create it from `getCreateTokenTableSql()`); Redis gains a `<name>:__hist` hash. A per-token Bernoulli or Complement model stored earlier has its histograms built in the store on first load or training write, once — proportional to the model, and blocking on Redis, so call `rebuildTokenHistograms()` off-peak for a large one. Bernoulli's histogram moves from the rows a write already locks, so a Bernoulli model is written as concurrently as a multinomial one; a training write to a SQL Complement model locks the model's counters row first, so those writes to one model are serialized. A third-party `IBayesianTokenStorage` that does not implement the new interface behaves as before (`bayesian_classifier_aggregate_missing` after incremental training).
- `TBayesianPayload`: typed reads out of decoded payloads and configuration arrays, which reads decoded payloads without casts of `mixed`.
- PHP 8.4 and 8.5 are supported and verified: CI runs them, and the suite has been run under both locally with deprecations displayed.
- `TBayesianService` access control, opt-in and PRADO-native: `<allow>`/`<deny>` rules inside an `<authorization>` element of the service (or an `authorization` list in PHP configuration; `getAuthorizationRules()` from code), evaluated in `run()` against the application user with `401`/`403` JSON errors (`bayesian_service_unauthorized`) and failing closed with `401` `bayesian_service_user_required` when rules exist but no user manager does; and `IPermissions` with the `bayesian_classify` and `bayesian_recommend` permissions (`PERM_CLASSIFY`, `PERM_RECOMMEND`), checked through the `dyClassify`/`dyRecommend` dynamic events when a `TPermissionsManager` is configured (`bayesian_service_permission_denied`). The docs now say plainly that the service must not be exposed unrestricted.
- `TBayesianService::MaxCandidates` (default 100, `0` = unlimited) caps the `recommend` candidate count (`413` `bayesian_service_candidates_too_many`), and `MaxTextLength` now also bounds the joined `context` and each candidate.
- Stored format versions: every payload carries `formatVersion` (`TNaiveBayesClassifier::FORMAT_VERSION`, currently 1); a payload without one reads as version 1, and a newer one is refused with `bayesian_model_format_unsupported`. Per-token metadata carries the storage's `layoutVersion` (`TOKEN_LAYOUT_VERSION`, now 2 in both `TSqlBayesianStorage` and `TRedisBayesianStorage`); a newer one is refused with `bayesian_storage_layout_unsupported`.
- `TFileBayesianStorage::FileMode` (default `0644`) and `DirectoryMode` (default `0755`), accepting an integer or an octal string.
- `TLazyBayesianVocabulary::refresh()` re-reads a model's totals from storage; `getMaxBatchTokens()`/`setMaxBatchTokens()`.
- Negative deltas: `IBayesianTokenStorage::applyDeltas()` accepts them, clamps every count at zero, and never shrinks the vocabulary — the contract a later "untrain" needs.
- `tests/unit/PackageClassMapTest.php` checks that every source class is in `config/prado-bayesian-classes.json`, every short name resolves, every error code raised is defined in `config/errorMessages.txt`, defined codes are raised and documented, and every message resolves.
- `tests/benchmark/benchmark-storage.php` (`composer benchmark`) reproduces the model-size and load-time figures in `docs/storage.md`.
- Composer scripts `lint`, `cs`, `fix`, `stan`, `fulltest` (lint → cs → stan → unittest) and `benchmark`; CI calls the same scripts.
- `SECURITY.md` (supported versions, how to report), `CONTRIBUTING.md` (the full check, backend environment variables), `.gitattributes` with `export-ignore` for tests, docs, build and agent files, and a stated pre-1.0 compatibility policy in the README.
- CI: PHP 8.4 and 8.5 legs, a `--prefer-lowest` leg on PHP 8.1, a weekly scheduled run (the package tracks PRADO `dev-master`), a cache key that hashes `composer.json` (the previous key hashed the gitignored `composer.lock` and never matched), and a corrected comment about how the framework is resolved. The 93% coverage floor is unchanged. The lowest-deps leg floors the transitive `phar-io/composer-distributor` at 1.0.2 (older releases react to every package's install event and 404 fetching a phpDocumentor phar named after that package's version), and the `phpstan/phpstan` dev constraint is `^2.1.22`, the first release that accepts PHP 8.5 as the analysed version.

### Changed
- **Per-token storage layout 2 (migration).** Both per-token backends store counters they can increment: `TSqlBayesianStorage` adds a `<table>_vocab` table (one row per distinct token) and a `<table>_counters` table, and derives the document total from the category rows; `TRedisBayesianStorage` keeps the category scalars in two integer hashes (`:__catdocs`, `:__cattoks`) instead of one packed hash, and derives the totals from the token set and the category hash. A model written by 0.1.0 is upgraded in place, inside one transaction, the first time it is read; nothing needs to be re-trained. With `AutoCreateTable="false"`, create the two new SQL tables from `getCreateTokenTableSql($driver)` before upgrading.
- **`IBayesianTokenStorage::applyDeltas()` semantics.** `$categoryStats` is now the category's *increments* (`documentCount`, `totalTokens`), not its new absolute values; the `totalDocuments` and `vocabularySize` keys of `$meta` are ignored (the implementation derives them and `loadTokenMeta()` returns the derived values); an empty `$meta` leaves the stored metadata untouched. A custom implementation must apply the call as an atomic increment. `TLazyBayesianVocabulary::applyDocument()` sends increments, re-reads the scalars from storage afterwards, and returns the stored metadata rather than the metadata it wrote.
- `TSqlBayesianStorage::Table` must now be at most 48 characters, so the derived per-token table and index names fit every driver's identifier limit.
- `TRedisBayesianStorage` rejects model names containing `:__`, the sequence its per-token sub-keys start with (a model named `m:__t:x` shared a key with token `x` of model `m`), and deletes a per-token model with one Lua script so a trainer racing the delete cannot leave orphan keys. Redis Cluster is not supported by the per-token mode (the scripts touch keys derived from the model name); the docs say so.
- `TBayesianService::runService()` declares its parameter as `array`; `bayesian_service_text_too_long` now names the parameter that was too long.
- `TBayesianModule` checks the class it instantiated for a `<classifier>`, `<tokenizer>` or `<storage>` element at runtime instead of assuming it.
- README and docs no longer call the scores "calibrated probabilities": they are normalized Naive Bayes scores, and the Concepts page says why they should be read as a ranking. The README's claim that `composer.json` declares a framework VCS repository is corrected (it does not; PRADO resolves from Packagist), and the performance figures are now those of `composer benchmark`.
- PHPStan runs at level 3 (was 2), analysed as PHP 8.5. The source is written to level 9 as well: decoded payloads and configuration arrays are read through `TBayesianPayload` rather than cast, and the only level-9 findings are three runtime null checks in `TBayesianService` around `getUser()` and `getApplication()`, which the framework declares non-null although both are null before authentication or outside a request.
- `IBayesianClassifier` gained `untrain()` and `untrainOne()`, and `IBayesianVocabulary` gained `removeDocument()`: a custom implementation of either interface must add them.
- The vocabulary semantics under withdrawal: a token is in the vocabulary while at least one training document contains it. `TLazyBayesianVocabulary::hasToken()` now answers from the document frequency rather than from the presence of a row, and a per-token category with zero documents is not listed. Under training alone nothing changes.
- `bayesian_service_action_unknown` now names `tag` among the actions.
- `AGENTS.md` no longer contradicts itself about the namespace and `framework/classes.php`, and names 0.2.0 as the next release.

### Known limitations
- Whole-payload storage (`TMemoryBayesianStorage`, `TFileBayesianStorage`, and `Mode="payload"` on SQL and Redis) is single-writer: a save replaces the whole model, so concurrent trainers lose each other's documents. Use `Mode="token"` for concurrent training.

## [0.1.0] - 2026-08-25

First public pre-release. Targets the PRADO `master` branch (upcoming 4.4): the extension is
registered through `composer.json` `extra.prado.bootstrap`, and its `config/errorMessages.txt`
and `config/prado-bayesian-classes.json` load system-wide via `extra.prado.error-messages` and
`extra.prado.class-map`. Not compatible with PRADO 4.3.x. APIs may change before 1.0.0.

Classes are namespaced under `Belisoful\Prado\Util\Bayesian` (`Classifier`, `Tokenizer`, `Math`,
`Evaluation`, and `Storage` sub-namespaces), except `TBayesianService`, which lives at
`Belisoful\Prado\Web\Services\TBayesianService`. The PSR-4 root is `Belisoful\Prado\` → `src/`:
the tree mirrors the framework's own layout so a class sits where a PRADO developer expects it,
under a vendor prefix that keeps it out of `Prado\` itself. Every class is also registered under
its Prado3-style short name, so application configuration can use either form.

### Added
- `TNaiveBayesClassifier` (multinomial Naive Bayes with Laplace smoothing and optional TF-IDF), plus `TMultinomialNaiveBayes`, `TBernoulliNaiveBayes`, and `TComplementNaiveBayes` (WCNB) variants behind one `IBayesianClassifier` contract.
- `TBayesianVocabulary` / `TBayesianCategory` / `TBayesianTrainingSet` training statistics; `TBayesMath` (log-space arithmetic) and `TFIdf`.
- Tokenizers: `TWordTokenizer`, `TNGramTokenizer` (character/word), `TRegexTokenizer`, `TBayesianTokenizerChain`, all behind `IBayesianTokenizer` and sharing `TBayesianTokenizerTrait` (property-list driven `exportConfig()`/`importConfig()`, safe `matchAll()`); `TBayesianTokenizerFactory` serializes/restores tokenizers, scrubs invalid UTF-8, and validates regex patterns.
- `TSqlBayesianStorage` configures its connection through `Prado\Data\TDbPropertiesTrait`, the same way the framework's other database-backed components do: `ConnectionID` resolves a `TDataSourceConfig` module and shares its connection, falling back to the storage's own DSN properties or an injected connection, and `getHasDbConnection()` / `deactivateDbConnection()` / `getTableGateway()` come with it. An unset `ConnectionID` reads as `''`, per the framework convention.
- Storage backends behind `IBayesianStorage`: `TMemoryBayesianStorage`, `TFileBayesianStorage` (atomic JSON files), `TSqlBayesianStorage` (SQLite/MySQL/PostgreSQL via `TDbConnection`, driver-aware DDL, `AutoCreateTable`), `TRedisBayesianStorage` (ext-redis).
- `TBayesianRecommender` / `IBayesianRecommender` ranking candidates by P(positive | context + candidate).
- `TConfusionMatrix` and `TBayesianMetrics` (accuracy, precision, recall, F1, macro/micro).
- `TBayesianModule` (`TModule` bootstrap named in `extra.prado.bootstrap`; `<classifier>`/`<storage>` child elements, `DefaultClassifier` eager load). Several `<classifier id="..." Model="...">` elements may share one storage backend, each with its own variant and its own `<tokenizer>`; `getClassifier($id)` selects between them and `DefaultClassifierID` picks the default.
- `TBayesianService` (read-only JSON `classify`/`recommend` HTTP actions with JSON error responses, `MaxTextLength`, `ModuleID`).
- Per-token storage for `TSqlBayesianStorage` and `TRedisBayesianStorage`. With `Mode="token"` a model is stored per (token, category) — SQL rows, or a Redis hash per token — rather than one JSON payload, and a classifier scores a document by reading only that document's tokens through `TLazyBayesianVocabulary`. On a 100,000-token SQL model that is 0.7 ms and 0.2 MB to load against 106 ms and 44.1 MB; the SQL model is bounded by the database, the Redis model by the Redis instance's RAM (which still holds it whole). Scores are identical to the whole-payload layout in both backends.
- Training against per-token storage is incremental: `trainOne()` writes only the document's rows instead of re-serializing the model, about 11x faster on a 100,000-token SQL model and independent of its size. The Redis backend applies the deltas with `HINCRBY`, so a document's counts accumulate atomically with no read-modify-write.
- `IBayesianVocabulary` (implemented by `TBayesianVocabulary` and `TLazyBayesianVocabulary`) and `IBayesianTokenStorage`, the two seams the above runs through. `TFIdf::idf()` and `weight()` take document-frequency counts rather than the whole map.
- `TBayesianModelConverter` rewrites a whole-payload model into a per-token backend without retraining — one model or every model a backend holds, across backends or in place within one database. It reads the classifier variant from the model's stored `kind`, so a caller need not know which variant each model is. Conversion is exact; the reverse direction is not offered, since the per-token layout deliberately cannot enumerate its vocabulary.
- `docs/`: concepts (the pipeline, the three event models, smoothing, TF-IDF, log-space math, tokenization, evaluation), a class reference, the storage-backend guide (including measured model sizes and the memory each backend costs), and configuration in both XML and PHP form, including every error code.

### Behavior
- Out-of-vocabulary tokens are skipped at classification time in every variant, rather than contributing a smoothed penalty that would bias novel documents toward the smallest category.
- The saved model state includes the tokenizer class and configuration, so `load()` restores the tokenizer a model was trained with.
- Each classifier variant writes a `kind` marker and refuses payloads of another kind (`bayesian_classifier_kind_mismatch`); `naive-bayes` and `multinomial-naive-bayes` are interchangeable.
- `setAlpha()` requires a positive finite value (`bayesian_alpha_invalid`); a trained classifier whose every category scores −INF/NaN throws `bayesian_classifier_score_undefined` rather than `bayesian_classifier_not_trained`.
- Tokenizers throw `bayesian_tokenizer_pattern_invalid` on a non-compiling pattern and `bayesian_tokenizer_pattern_failed` when PCRE fails at match time (backtrack limit); invalid UTF-8 input is scrubbed rather than emptying the token list. `TRegexTokenizer` uses the first capturing group consistently (an unmatched optional group yields no token). `TNGramTokenizer` normalizes whitespace in character mode.
- Every storage backend returns `list()` sorted ascending by name; the persistent backends report a payload that is present but unparseable as a missing model rather than throwing.
- Bernoulli classification is O(document x categories), not O(vocabulary x categories). Absence is evidence in the Bernoulli model, but the absent-token mass is a constant per category, so it is summed once and cached and each document only corrects it for the tokens it contains — arithmetically identical to the literal sum over the vocabulary.
- The derived caches that Bernoulli and Complement keep are keyed on a vocabulary state signature that changes on any mutation, including one made directly on a category obtained from `getVocabulary()`. A stale aggregate would shift scores silently rather than raise, so the key covers more than the document and category totals.
- `TFileBayesianStorage` writes through a unique temp file with `LOCK_EX`; an empty `Directory` is treated as unset. `TSqlBayesianStorage` uses `VARCHAR(191)`/`LONGTEXT`/`BIGINT` on MySQL and creates the table once per connection; JSON encoding failures throw in every backend. `TRedisBayesianStorage` checks `AUTH`/`SELECT`/write results.
- `TBayesianModule::init()` applies `DefaultClassifier` even without a `<classifier>` element and only loads a model that `exists()`; storage errors propagate instead of being swallowed. Configured classes are resolved and type-checked before instantiation.
- `TBayesianService` returns JSON errors (`400`/`413`/`503`) for bad parameters, oversize text, or an untrained model; malformed (array-valued) parameters are rejected; recommend `scores` are always a JSON object; responses carry `X-Content-Type-Options: nosniff`.
- `TBayesianRecommender` ignores blank candidates, throws when the classifier is untrained, and throws `bayesian_recommender_category_unknown` when its `PositiveCategory` is not one of the classifier's trained categories. `TBayesianMetrics::getF1()` returns `0.0` (not NaN) when precision and recall are both defined and zero, and per-label metrics reject unregistered labels.

### Packaging
- `pradosoft/prado` is a runtime requirement at `^4.4@dev`, not a development one, so Composer installs the framework with the package. It resolves straight from Packagist through the branch alias PRADO declares (`dev-master` → `4.4.x-dev`), so `composer.json` declares no framework repository — only `minimum-stability: dev` with `prefer-stable: true`. An application still lists the asset-packagist repository itself, since Composer reads `repositories` only from the root project and PRADO depends on `bower-asset/*`. Once PRADO 4.4 reaches a stable Packagist release the constraint can drop `@dev`.

### Testing
- CI runs the matrix (PHP 8.1/8.2/8.3) against Redis, MySQL 8, and PostgreSQL 16 service containers with `BAYESIAN_REQUIRE_BACKENDS=1`, so a backend that is unavailable fails the build instead of silently skipping its tests. The MySQL and PostgreSQL round-trips cover the driver-aware DDL, the upsert, and a payload larger than MySQL's 64 KB `TEXT` limit.
- `composer coverage` reports line coverage and CI enforces a floor (`tests/test_tools/check-coverage.php`).
- `composer integration` (`tests/integration/`) installs the extension into a throwaway consumer project through Composer and verifies the `extra.prado` error-messages, class-map, and bootstrap wiring plus a served request; it runs as its own CI job.
